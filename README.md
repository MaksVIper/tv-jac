# tv-jac

Express-приложение для отображения готовых заказов из существующей MySQL-базы Jaco.

## Требования

- Node.js 22 или новее
- MySQL 8/MariaDB с доступом к `jaco_main_rolls` и базам точек
- отдельный пользователь MySQL только с правами `SELECT`

## Установка и запуск

```bash
npm install
copy .env.example .env
npm start
```

Перед production-запуском обязательно замените `DB_PASSWORD` и `CSRF_SECRET` в `.env`.
Секрет можно создать командой:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Основные страницы:

- `http://127.0.0.1:3000/border` — выбор точки и табло;
- `http://127.0.0.1:3000/tv/1` — табло конкретной точки;
- `http://127.0.0.1:3000/health` — проверка процесса.

## Конфигурация

Параметры находятся в `.env.example`. Для публикации на всех интерфейсах задайте
`HOST=0.0.0.0`. При работе напрямую по HTTP оставьте `COOKIE_SECURE=false`. Если HTTPS
завершается в самом Node.js или перед приложением, cookie и настройки доверенного proxy
нужно согласовать с этой схемой развёртывания.

Даты и окно показа заказов считаются в `APP_TIMEZONE` (`Europe/Samara`, UTC+4), как в Laravel `jaco`.
Если считать «сейчас» по Москве (UTC+3), порог `give_data_time` сдвигается примерно на час назад и на табло попадают лишние заказы.

Приложение использует данные:

- `jaco_main_rolls.points` и `jaco_main_rolls.cities`;
- `jaco_main_rolls.points_tv_settings`;
- `<points.base>.orders`.

Имя базы точки принимается только из `points.base`, проверяется и экранируется. Значения
из HTTP-запросов передаются в SQL только параметрами.

## Логи

В `logs/application.log` и в stdout пишутся только ошибки и исключения (уровень
`error` и выше). Успешные запросы, 4xx и служебные сообщения не сохраняются.
Раз в сутки файл обнуляется: ротация удаляет вчерашний лог, архивы не хранятся.
Cookies, заголовки авторизации и CSRF-токены маскируются.

## Защита от нагрузки

Включены Helmet/CSP, CSRF, same-origin проверка, лимиты тела запроса, общий и отдельный
лимит polling, ограничение одновременных запросов, пула MySQL и HTTP-таймауты.

Это защищает процесс и базу от умеренного злоупотребления, но приложение без reverse
proxy не способно остановить DDoS, который насыщает сетевой канал или исчерпывает
соединения до Node.js. Для публичного production-сервиса необходим внешний WAF/CDN
(например, Cloudflare) либо Nginx/HAProxy с сетевыми лимитами.
